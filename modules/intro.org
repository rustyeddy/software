#+title: Intro Module Outline

* Purpose
Establish the mental model for the course: delivering production
software with human, AI, or hybrid teams. Introduce the engineering
principles and iterative loops that later modules put into practice.
This is a working outline, not the finished lesson material.

* Learning outcomes
By the end of the module, students can:
- Distinguish producing code from delivering useful, reliable software.
- Explain what AI changes and what remains fundamental to engineering.
- Describe the project delivery loop and the developer task loop.
- Apply the course blueprint proportionately to a new or existing project.

* TODO Lesson 1: What software engineering is really about
** Outcome
Understand the responsibilities of delivering production-quality
software regardless of who writes the code.
** Topics
- Software exists to solve customer problems and deliver value.
- Writing code is only one part of software development.
- Demonstrations versus production: reliability, security, maintainability
  and operation under real conditions.
- Managing complexity, uncertainty, quality and change.
- What AI changes: delegation, implementation speed and coordination.
- What AI does not remove: requirements, design, verification and
  accountability. A human or organization remains accountable.
** Example
Contrast a working demonstration with a service that customers depend
on, including what happens when something fails or requirements change.
** Takeaway
Producing code is not the objective; delivering useful, reliable
software is.

* TODO Lesson 2: The delivery loop: idea -> production -> feedback
** Outcome
Explain the recurring activities of a software project and how
individual developer tasks fit within them.
** Topics
- Planning: what problem are we solving?
- Design: how should we solve it?
- Setup: how will the team work? Bootstrap initially and evolve as needed.
- Developing: how do we implement and verify the solution?
- Delivering: how do we get it into customers' hands?
- Production: how do we keep it working?
- Feedback: what have we learned and what should we change?
- Project delivery loop: idea -> planning -> design -> development ->
  delivery -> production -> feedback -> next iteration.
- Developer task loop: understand the task -> implement -> build/test ->
  review -> revise as necessary -> integrate.
- Activities overlap and recur; these are not waterfall gates.
  Requirements, design, testing, security and documentation evolve.
- Humans and AI agents can participate throughout both loops, with
  appropriate authority and verification.
** Example
Trace a small customer request through delivery, then show how
production feedback changes the next iteration. Zoom into one task
and its review/revision cycle.
** Takeaway
Development is a continuous process of learning, building, verifying,
delivering and improving.

* TODO Lesson 3: How to use this course as a checklist
** Outcome
Use the course as a practical project blueprint rather than a rigid
process prescription.
** Topics
- Starting a new project or assessing an existing one.
- Tailoring the process to risk, team size and project maturity.
- Applying the same principles to human, AI and hybrid teams.
- Selecting a project to work through during the course.
- Building reusable assets incrementally as lessons are developed.
- Using the engineering checklist to identify gaps and next actions.
** Exercise and proposed student asset
Create a short project baseline: problem, intended customer or user,
desired outcome, current state, team composition, and one next action.
For a new project, mark unknowns rather than inventing requirements.
Keep this lightweight; the Planning module develops these ideas.
A reusable one-page baseline worksheet is a candidate asset, not a
commitment to a particular format.
** Takeaway
The process serves the project, not the other way around.
